เส้นทางหลัก · ใบเบิก → ตัดสต๊อก

ไล่ตามลำดับเวลาจริง 3 องก์ — ใบเบิกถูกสร้าง (ฝ่ายขาย) → ของถูกตัดสต๊อก (ฝ่ายจัดของ) → ตรวจสอบ/แก้ไข (แอดมิน)

/shopee/new · /shopee/import

สร้างใบเบิก หรือ นำเข้า Excel

พิมพ์เองทีละใบด้วย dropdown หรืออัปโหลดไฟล์ Shopee ทีละหลายร้อยออร์เดอร์

◆ ออกแบบยังไงให้ง่าย
  • Dropdown ค้นหาได้ทุกช่อง — กลิ่น/ขนาด/จังหวัด เลือกจากลิสต์ พิมพ์เองไม่ได้ → กันสะกดผิด กันชื่อกลิ่นไม่ตรง
  • จังหวัด → อำเภอ → รหัสไปรษณีย์ auto-fill — เลือกจังหวัดแล้วที่เหลือเติมให้
  • Import = พรีวิว + ตรวจก่อนบันทึก — เห็นว่าจะเข้ากี่ใบ แถวไหน error ก่อนกดยืนยัน
  • เตือน Order No. ซ้ำ — Order No. คือกุญแจหลัก ระบบกันสร้างซ้ำ
2
/api/print/[orderNo] · PDF

พิมพ์ใบเบิก (มีบาร์โค้ด Order No.)

◆ ออกแบบยังไงให้ง่าย
  • บาร์โค้ด Code128 ตัวใหญ่ชัด — สแกนตัดสต๊อกทีหลังได้ใน 1 วินาที ไม่ต้องพิมพ์เลขยาว
  • ต้นฉบับ + สำเนา ในหน้าเดียว — ครบทุกช่องตามฟอร์มจริง
  • เลขที่ใบเบิกออกอัตโนมัติ — SH-YY-MM-DD-#### กันเลขซ้ำ/ตกหล่น

ขั้นตรวจก่อนตัด

◆ ออกแบบยังไงให้ง่าย
  • เห็นทั้งใบก่อนตัด — กลิ่น ขนาด จำนวน คงเหลือ ครบ ป้องกันตัดผิดใบ

  • ปุ่มยืนยันใหญ่ท้ายรายการ — ต้องกดเองเสมอ ระบบไม่ตัดให้อัตโนมัติ

ดูภาพรวมสุขภาพสต๊อก

หน้าแรกสรุปสถานะทั้งร้าน — ของใกล้หมด กลิ่นที่เบิกมากสุด ยอดตัดวันนี้

◆ ออกแบบยังไงให้ง่าย

  • กลิ่นเบิกมากสุด 10 อันดับ + "ดูทั้งหมด" — เห็นภาพรวมเร็ว เจาะลึกได้เมื่ออยากดู
  • บันทึกการใช้งาน (audit) — แอดมินย้อนดูได้ว่าใครเข้าใช้/ตัด/รับเข้า/แก้กลิ่น เมื่อไร

ยกเลิกการตัด → แก้ไข → ตัดใหม่

◆ ออกแบบยังไงให้ง่าย
  • ยกเลิกได้ (คืนสต๊อก) — ตาข่ายกันพลาด ฝ่ายจัดของทำงานกล้าขึ้น ไม่กลัวตัดผิด
  • ขอบเขตชัด — แอดมิน = ยกเลิกใบไหนก็ได้ · ฝ่ายจัดของ = เฉพาะใบที่ตัวเองตัด ภายใน 24 ชม.
  • ยกเลิกแล้วพาไปหน้าใบเบิกทันที — ไม่ต้องเดินหาว่าใบไปอยู่ไหน แก้/ตัดใหม่ได้เลย

ระบบย่อยที่ ฝ่ายคลัง ใช้จัดการของก่อนบรรจุ — น้ำหอมยังไม่บรรจุ, สติ๊กเกอร์/การ์ด, ขวด/แพ็คเกจ · แยกกลุ่มตามเกรด (EDP·EDP+·PARFUM·EDT) พับ/กางได้ รับเข้า-เบิกทีละหลายรายการ และนับทั้งคลังจากไฟล์เดียว

💻 Desktop · /stock/count
1
ดาวน์โหลดเทมเพลต

โหลดไฟล์ Excel ที่เติมยอดปัจจุบันให้แล้ว

ปุ่มเดียวได้ไฟล์ 4 ชีต (สำเร็จรูป · น้ำหอม · สติ๊กเกอร์ · ขวดและแพ็คเกจ) ทุก SKU มีอยู่พร้อมยอดล่าสุด

◆ ออกแบบยังไงให้ง่าย
  • Pre-filled ทุกแถว — ไม่ต้องพิมพ์รายการเอง แค่เดินนับแล้วเติมช่อง "นับได้จริง"
  • เรียงตามเกรด — EDP → EDP+ → PARFUM → EDT → น้ำปรุง (OEM ล่างสุด) ตรงกับหน้าจอ เดินนับไล่ลงได้
  • คอลัมน์ "รหัส (ห้ามแก้)" — ผูกแต่ละแถวกับของจริง ปลอดภัยแม้ชื่อซ้ำ
2
อัปโหลด → พรีวิวส่วนต่าง

เห็นส่วนต่างก่อนปรับจริง

อัปไฟล์ที่นับแล้วกลับเข้าระบบ → แสดงตารางเฉพาะแถวที่ยอดเปลี่ยน (เพิ่ม/ลด) ให้ตรวจก่อนกดยืนยัน

◆ ออกแบบยังไงให้ง่าย
  • ช่องว่าง = ข้าม — ไม่ได้นับแถวไหนก็เว้นไว้ ระบบไม่แตะยอดเดิม
  • โชว์เฉพาะที่ต่าง — นับ 300 แถวแต่เปลี่ยนจริง 12 → เห็นแค่ 12 ตรวจง่าย
  • ปรับใน transaction เดียว + ลง audit — บันทึกส่วนต่างเป็นการเคลื่อนไหว ย้อนดูได้

ทำไมแยก "คลังวัตถุดิบ" ออกจาก "สินค้าสำเร็จรูป"

ของก่อนบรรจุ (น้ำหอม·ป้าย·ขวด) นับหน่วยและจัดกลุ่มคนละแบบกับสินค้าพร้อมขาย และเป็นงานของฝ่ายคลังคนละมือกับฝ่ายจัดของ — แยกเมนู แยกสิทธิ์ ทำให้แต่ละฝ่ายเห็นเฉพาะงานตัวเอง แต่ยอดทั้งหมดนับรวมได้จากไฟล์เดียว

04

  • ยกเลิกการตัด (ใบไหนก็ได้)

  • ดูบันทึกการใช้งาน (audit)

  • ถังขยะ (ลบ/กู้คืน)
  • ตัดสต๊อก / สแกนใบเบิก
  • ดูสต๊อก · คลังวัตถุดิบ · Dashboard

เส้นทางส่งงานระหว่างฝ่าย

ฝ่ายคลัง รับเข้าวัตถุดิบ+บรรจุเป็นสินค้าสำเร็จรูป → ฝ่ายขาย สร้างใบเบิก+พิมพ์ (มีบาร์โค้ด) → ฝ่ายจัดของ สแกน+ใส่ SKU/Spec → ตัดสต๊อก · ถ้าพลาด แอดมิน ยกเลิกใบไหนก็ได้ · แต่ละฝ่ายเข้าระบบมาเจอแต่หน้างานตัวเอง

สิ่งที่ต้องทำก่อนใช้จริงบน prod

รัน SQL ที่ค้างบน Supabase: RUN_ALL_FIXES.sql (แก้เกรด/ชื่อ/ป้าย), ADD_jen_spray_black.sql (หัวสเปรย์ JEN สีเงิน/ดำ), และ RUN_ON_PROD_materials.sql ถ้ายังไม่ได้ seed คลังวัตถุดิบ — จากนั้นเทมเพลตหน้า "อัปเดตยอด (ไฟล์)" จะข้อมูลตรงทั้งหมด · ของตัวอย่าง 1.2/4 ml ที่ยังไม่มียอด ต้อง "รับเข้า" ก่อน ไม่งั้นตัดแล้วขึ้นการ์ดเหลือง (ติดลบ)

06

มือถือ vs เดสก์ท็อป

ต่างคนต่างอุปกรณ์ ต่างบริบท — ออกแบบคนละแบบตามงานจริง

📱 ฝ่ายจัดของ = มือถือหน้าชั้นวาง

เมนูซ้อนแนวตั้ง ปุ่มเต็มความกว้าง แตะนิ้วโป้งถึง ช่องสแกนโฟกัสรอ เทสต์ที่ 375px

💻 เจ้าของ/ขาย/คลัง = เดสก์ท็อปหลังร้าน

ตาราง/แดชบอร์ด/คลังวัตถุดิบกว้าง เห็นข้อมูลเยอะพร้อมกัน กรอง/ค้นหา/พับกลุ่ม/พิมพ์สะดวก
