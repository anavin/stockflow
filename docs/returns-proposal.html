รับคืนสินค้า — คืนเข้าสต๊อก หรือ ตีชำรุด

เมื่อลูกค้าส่งของกลับ (ตีกลับ/ไม่รับ/เปลี่ยนใจ/ของเสีย) พนักงาน สแกน Order No. เดิม แล้วตัดสินใจต่อชิ้นว่า คืนเข้าสต๊อกขายได้ หรือ ตีเป็นของชำรุด — ไหลตามระบบเดิมทุกจุด (สแกน + ledger + กันซ้ำ)

💡

ทำไมต้องมี: ตอนนี้มีแค่ "ยกเลิกการตัดสต๊อก" (reverseIssue) ที่คืนสต๊อกทั้งใบ — แต่นั่นคือ "แก้ตอนตัดผิด" ไม่ใช่ "รับของคืนจริง" · การรับคืนต้องเลือกได้ทีละชิ้น + แยกของดี/ของเสีย + มีเหตุผล + คืนได้บางส่วน

✅

ข้อสรุปที่ล็อกแล้ว: (1) ของชำรุดมี ตารางคลังของเสีย (damaged) แยก + หน้า /stock/damaged  ·  (2) รับคืนได้เฉพาะออเดอร์ที่ส่งแล้ว (shipped_at ไม่ null)  ·  สถานะ: ออกแบบเสร็จ รอสั่งลงมือ

01

เส้นทางการทำงาน

ใช้โครงเดียวกับหน้า "จัดส่ง" — สแกน Order No. จากใบปะหน้า/ใบเบิกที่ตีกลับมา แล้วจัดการรายชิ้น

STEP 1

สแกน Order No.

ยิงบาร์โค้ดใบเบิกที่ตีกลับ → ดึงรายการ · รับคืนได้เฉพาะออเดอร์ที่ "ส่งแล้ว" (ยังไม่ส่ง → ใช้ยกเลิกออเดอร์/ยกเลิกการตัดแทน)

→
STEP 2

เลือกต่อชิ้น

แต่ละรายการ: จำนวนที่คืน + เลือก คืนสต๊อก หรือ ชำรุด

→
STEP 3

ใส่เหตุผล

ตีกลับ/ไม่รับ/เปลี่ยนใจ/เสียจากขนส่ง + หมายเหตุ (ต่อใบ)

→
STEP 4

ยืนยัน

คืนสต๊อก +qty · ชำรุดเข้าคลังของเสีย · บันทึก ledger + audit

03

2 ปลายทาง — ทำอะไรกับข้อมูล

เลือกความหมายผลต่อสต๊อกบันทึก ledger
✓ คืนสต๊อก ของสภาพดี ขายต่อได้ → คืนเข้าคลังปกติ stock.qty += จำนวน (ขนาดที่ติดตามเท่านั้น) stock_moves reason 'return' (+qty, ผูก order_no)
⚠ ชำรุด ของเสีย/แตก/ใช้ไม่ได้ → แยกออก ไม่เข้าสต๊อกขาย stock ไม่ขยับ · เข้าคลังของเสีย damaged.qty += จำนวน stock_moves reason 'damage' (ไว้ตรวจ/เคลม/ทำลายต่อ)

ของชำรุด ไม่ปนสต๊อกขาย เด็ดขาด — มีหน้า "สต๊อกของชำรุด" แยก ไว้ตัดสินใจต่อ (เคลมขนส่ง / ทำลาย / ซ่อม)

04

โครงข้อมูล (สอดคล้องระบบเดิม)

ต่อยอดจากตารางเดิม ไม่รื้อ — เพิ่ม reason ใน ledger เดิม + 2 ตารางเล็ก + 1 คอลัมน์บน orders

-- 1) ledger เดิม stock_moves — reason เป็น text อยู่แล้ว (issue/receive/adjust) เพิ่มได้เลย
reason: 'return'   // คืนเข้าสต๊อก (+qty, มี order_no + note)
reason: 'damage'   // ตีชำรุด (log ไว้ ไม่ขยับ stock ขาย)

-- 2) order_returns — ประวัติการคืนราย "บรรทัด" (audit ครบ + กันคืนเกิน)
create table order_returns (
  id, order_no, line_no, product, size,
  qty int, disposition -- 'restock' | 'damaged',
  reason text, note text, created_at, created_by
);

-- 3) damaged — ยอดของชำรุดคงเหลือต่อ SKU (คู่ขนานกับ stock)
create table damaged ( product, size, qty, updated_at );

-- 4) orders — ธงไว้กรอง/รู้สถานะเร็ว
orders.returned_at       // คืนครั้งแรกเมื่อไร (null = ยังไม่คืน)
orders.return_status    // 'none' | 'partial' | 'full' → โชว์ป้ายบนรายการ/จัดส่ง

-- 5) ลูกค้าคืนบ่อย — ไม่ต้องมีตารางใหม่ คำนวณจาก order_returns join orders
--    ตาม key เดิมของ CustomerSuggest (username / phone / receiver)
returnCount(customer) = count(distinct order_no ที่มี order_returns)
// ≥ เกณฑ์ (เช่น 3 ครั้ง หรือ rate สูง) → ป้ายเตือนตอนสร้างออเดอร์ใหม่
  • กันคืนเกิน: รวม qty ที่คืนแล้วต่อบรรทัด (order_returns) ต้อง ≤ จำนวนที่ส่ง — เกินไม่ให้ยืนยัน
  • คืนบางส่วน/หลายรอบ: คืน 2 จาก 3 วันนี้ อีก 1 พรุ่งนี้ก็ได้ — order_returns เก็บทุกรอบ
  • ขนาดตัวอย่าง 1.2/4 ml คืนสต๊อกเฉพาะขนาดที่ติดตาม (STOCK_TRACKED_SIZES) เหมือนตอนตัด
05

อิงระบบเดิมทุกจุด

📷 สแกน + แจ้งผล

ใช้ CameraScan ตัวเดิม — สแกน Order No. + overlay ผลรายชิ้น (คืนสต๊อก ✓ / ชำรุด ⚠ / ไม่พบ ✕) เหมือนหน้าจัดส่ง

📒 Ledger เดียวกัน

บันทึกลง stock_moves เดิม (reason return/damage) → ประวัติวัตถุดิบ/สต๊อกเห็นครบ ตรวจย้อนได้

🔒 กันซ้ำแบบ atomic

เคลมด้วย FOR UPDATE + กันคืนเกินจำนวนส่ง — แนวเดียวกับ markShipped/reverseIssue ที่เพิ่งแก้

👤 สิทธิ์

รับคืน = picker / stock / admin (คนรับของจริง) · ลง logActivity('return') ให้แอดมินย้อนดู

🎨 โทน/คอมโพเนนต์

chip-ok=คืนสต๊อก · chip-danger=ชำรุด · .card / .btn / .alert เดิม · หน้ากว้าง max-w-6xl

🧭 เมนู

อยู่กลุ่ม สินค้าสำเร็จรูป → "รับคืนสินค้า" (/returns) + "สต๊อกของชำรุด" (/stock/damaged) + ประวัติการคืน

06

ลูกค้าคืนบ่อย — เตือนตอนรับออเดอร์ใหม่

ต่อยอด CustomerSuggest เดิม — พอเลือก/จับคู่ลูกค้าเก่าที่คืนบ่อย ขึ้นป้ายเตือนให้ระวังก่อนยืนยันออเดอร์ (กันโดนคืนซ้ำ/กันโกง)

📝 สร้างใบเบิกใหม่ · จับคู่ลูกค้าเดิม
ธนพร ส. · 08x-xxx-1234
⚠ ลูกค้าคืนบ่อย · คืน 4 จาก 7 ออเดอร์ ล่าสุด: ตีกลับ 12 ส.ค.
→ เติมที่อยู่/ประวัติให้เหมือนเดิม แต่เตือนให้ตรวจก่อนส่ง (เช่น แนะนำเก็บปลายทาง/ยืนยันที่อยู่)
  • ไม่ต้องมีตารางใหม่ — นับจำนวนคืนต่อลูกค้าจาก order_returns join orders ตาม key เดิม (ชื่อผู้ใช้/เบอร์/ผู้รับ)
  • เกณฑ์ปรับได้ — เช่น คืน ≥ 3 ครั้ง หรือ อัตราคืนสูง → ขึ้นป้ายแดง · ต่ำกว่านั้นไม่รบกวน
  • โชว์ที่ CustomerSuggest (ตอนพิมพ์ชื่อ/เลือกลูกค้า) + การ์ดประวัติลูกค้า — ที่เดียวกับที่ autofill อยู่แล้ว
07

ส่วนขยายให้ครอบคลุม

ปิดช่องโหว่ + ครบวงจร ตั้งแต่รับคืน จนของชำรุดมีทางออก และเห็นภาพรวมทั้งระบบ

↩ ยกเลิก/แก้การคืน

admin

บันทึกคืนผิด (คืนสต๊อกทั้งที่ชำรุด / จำนวนพลาด) → ย้อนได้: void แถว order_returns + กลับรายการ stock/damaged · ใช้ FOR UPDATE กันย้อนซ้ำ (แนวเดียวกับ reverseIssue)

🗑 จัดการของชำรุด

/stock/damaged

ของเสียไม่กองค้าง — ต่อชิ้นเลือก: ทำลาย(write-off) · เคลมขนส่ง · ซ่อมแล้วคืนสต๊อก (damaged → stock) · ลง ledger ทุกครั้ง

⚠ กัน edge "ส่งแต่ยังไม่ตัดสต๊อก"

ออเดอร์ที่ส่งแล้วแต่ stock_issued_at ยัง null → ของไม่เคยถูกหัก · คืน "เข้าสต๊อก" จะบวกเกิน → บล็อก/เตือน (โยงกับพฤติกรรมที่เว้นไว้ #1)

🏷 สถานะคืนบนรายการ

orders.return_status = คืนบางส่วน/คืนครบ → ป้าย คืนบางส่วน บนหน้ารายการออเดอร์ + จัดส่ง เห็นทั้งระบบ

📊 รายงานการคืน

อัตราคืนต่อกลิ่น (กลิ่นไหนถูกคืนบ่อย = คุณภาพ/ขนส่ง) + สรุปเหตุผลการคืน · ดึงจาก order_returns

🎁 ของแถม/ตัวอย่าง

ขนาด 1.2/4 ml (ไม่ track สต๊อก) — คืนได้แต่เข้าชำรุดอย่างเดียว ไม่บวกสต๊อกขาย (สอดคล้อง STOCK_TRACKED_SIZES)

08

ขอบเขต (ระบุให้ชัด)

💸 ไม่รวมเรื่องเงิน/refund

ระบบนี้ track "ของจริง" เท่านั้น (คืนสต๊อก/ของเสีย) · การคืนเงินลูกค้าจัดการใน Shopee ตามปกติ

ป้ายฉีก/บาร์โค้ดเสีย → พิมพ์ Order No. เอง ได้ (ช่องมีอยู่แล้วเหมือนหน้าจัดส่ง/ตัดสต๊อก)
